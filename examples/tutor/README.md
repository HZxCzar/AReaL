# Unified Tutor Environments

`examples/tutor` defines the shared environment contract for training tutor models on AReaL. A task adapter owns its native simulator and reward definitions; the shared workflow contract standardizes tutor turns, student-policy calls, trajectory records, and AReaL training output.

## Core contract

A tutor environment subclasses `TutorEnvironment` and implements:

```python
async def reset(episode: EpisodeInput) -> TutorObservation
async def compress_context(target: ContextTarget) -> CompressedContext
def build_student_prompt(...)
def parse_student_action(...)
def fallback_student_action(...)
async def apply_tutored_actions(...)
async def advance_untutored_participants(max_steps: int)
async def next_tutor_observation() -> TutorObservation
```

`step(TutorAction)` always executes one complete tutoring round:

```text
compressed tutor observation
  -> trainable tutor response generated by AReaL
  -> legal student action generation, repair, or fallback
  -> native task transition
  -> automatic frozen/untutored turns, if needed
  -> one TutorTurnRecord (one AReaL training sample)
```

A `TutorTurnRecord` stores the tutor observation, tutor generation metadata, selected student actions, environment event, and named reward components. The common workflow converts each record's tutor response into AReaL tensors (`input_ids`, `loss_mask`, `logprobs`, `versions`, and `rewards`). Automatic transitions update task state but never create a tutor-loss sample.

## Students, context, and legal actions

`StudentPool` is the policy interface used by every environment:

```python
async def act(participant: Participant, prompt: str) -> str
```

Each `Participant` records `participant_id`, `policy_id`, `role`, and `team`, allowing experiments to use different student models by role or side. The base environment retries invalid student responses up to `max_student_action_attempts`, then asks the task adapter for a deterministic legal fallback.

Each task owns `compress_context()`. Compression must preserve the current task state, useful recent history, private memory authorized for the active participant, and legal actions; it must discard superseded raw history and never leak hidden state into public/student context.

## Checkpointing and LoRA recovery

Task environments do not save or load LoRA adapters directly. The AReaL `PPOTrainer` owns actor/rollout versions, saver state, and recovery. Use the task YAML's shared identifiers consistently:

```yaml
experiment_name: tutor-grpo
trial_name: my-run
cluster:
  fileroot: /shared/results
saver:
  fileroot: ${cluster.fileroot}
  freq_steps: 25
recover:
  mode: auto
  fileroot: ${cluster.fileroot}
```

Keep `experiment_name`, `trial_name`, and `fileroot` unchanged when resuming. This lets AReaL restore the matching trainer state and LoRA/rollout checkpoint versions. Environments only preserve the current `ModelResponse` in their per-turn records.

### Math

The migrated math implementation remains in `examples/math_tutor` to preserve its existing AReaL training, LoRA-version, and pairwise-reward behavior. It uses an auxiliary student model and an optional answer judge. Key settings are in `examples/math_tutor/config.yaml` and `examples/math_tutor/configs/`.

### Hanabi

Hanabi tutors the active player on one legal card action per step. It accepts `env_kwargs` such as `scenario`, and reward coefficients including `consistency_coef`, `tutor_quality_coef`, `action_quality_coef`, `leakage_coef`, `direct_action_penalty`, and `task_reward_coef`.

Set `use_privileged_teacher_observation: false` for public-state tutoring. The adapter compresses the latest eight game events plus the active-player observation.

### Hidden Rule

The final directory name is intentionally `hiddeb_rule_tutor`. One step gives the tutor a fresh labeled-example batch, receives a student question/test/final hypothesis, and records one tutor training turn. `rounds` controls the maximum dialogue length; `examples_per_episode` controls generated evidence. The adapter retains the latest six dialogue turns in compressed context.

### Werewolf

Werewolf maps roles to two sides:

- `werewolf`: only the Werewolf role.
- `villager`: villager, witch, foreseer, hunter, and other non-werewolf roles.

Choose the tutoring intervention with disjoint sets that cover both sides:

```python
# Tutor villagers; simulate Werewolf turns with frozen student policies.
WerewolfTutorEnvironment(pool, tutored_sides=("villager",), frozen_sides=("werewolf",))

# Tutor both sides on their own turns.
WerewolfTutorEnvironment(pool, tutored_sides=("villager", "werewolf"), frozen_sides=())

# Tutor Werewolves while villagers are frozen.
WerewolfTutorEnvironment(pool, tutored_sides=("werewolf",), frozen_sides=("villager",))
```

When the active player belongs to a frozen side, the environment calls the corresponding student policy without tutor guidance and continues until the next tutor-eligible player. This also happens before the first tutor observation. Default compression contains the active participant's visible state and the last eight public events; set `use_privileged_teacher_observation=True` only for deliberately privileged teacher experiments.

## Adding a new environment

1. Implement a `TutorEnvironment` adapter under `examples/<task>_tutor/`.
2. Keep native task state and task-specific parsing inside that adapter.
3. Return named reward components so experiments can compare tutoring signals across tasks.
4. Add a task YAML with matching AReaL `saver` and `recover` identifiers.
5. Add a smoke test that exercises `reset()` and at least one `step()` with a deterministic `StudentPool`.
